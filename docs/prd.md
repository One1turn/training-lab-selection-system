## 1. 项目概述

**一句话目标**：把"学生实训室选组选拔"从人工汇总 Excel/邮件，变成一套**全流程线上、结果可追溯、双向往确认**的选组系统。

当前流程的问题不是"没有表单"，而是**信息在多轮次、多角色之间反复交接**：志愿分散在各班表格里，面试分数靠人工排序，拟录取靠电话/微信逐个确认，逾期释放和递补靠人盯，调剂靠开会拍脑袋，最终名单无法自证公正。本产品把这条链路固化成"轮次 + 状态机 + 审计日志"，让每一步都可复现、可申诉、可公示。

## 2. 目标用户

### 2.1 用户角色

| 角色 | 系统内标识 | 规模 | 核心场景 |
|---|---|---|---|
| 学生 | `student` | 主力用户，百人级 | 看方向/名额 → 填 3 个平行志愿 → 参加面试 → 确认唯一去向 → 看公示/提申诉 |
| 导师 | `mentor` | 每室 2-5 人 | 维护方向与考核要求、录入面试评分、看待录/递补候选 |
| 教务管理员 | `admin` | 1-3 人 | 建室建名额、排轮次、跑选拔、发布补录/调剂、公示、处理申诉 |
| 监督 / 申诉受理 | `auditor` | 1-2 人 | 只读查看全流程与审计日志，受理实名异议并出具复核意见 |

### 2.2 他们现在遇到的问题

- **志愿收不齐、对不上**：各班 Excel 格式不一，合表时漏人、重人、改错优先级。
- **分数排序不可复现**：人工排序，同分怎么处理没有规则，事后无法解释。
- **确认环节失控**：一人同时"答应"多个导师，或确认后又反悔，名额白占。
- **递补靠人盯**：谁逾期了、该补谁、补到第几位，全凭记忆与表格。
- **调剂无优先级**：内部调剂和跨室调剂混着做，学生觉得不公平。
- **公示无依据**：名单贴出来，但拿不出"为什么是他"的证据链。

### 2.3 本产品解决什么

| 问题 | 对应能力 |
|---|---|
| 志愿收不齐 | 统一在线填报，系统内强制上限 3 个、禁止重复、截止后锁定 |
| 排序不可复现 | 规则化算法：四维评分 → 总分 → 同分按学号，纯函数可单测 |
| 确认失控 | 单意向自动确认 / 多意向必须显式选一；确认即锁定，其余意向自动置为放弃 |
| 递补靠人盯 | 逾期自动释放 + 一键按顺位补录，且不超过实训室容量 |
| 调剂不公平 | 固定优先级：实训室内部 → 全院跨室 → 约谈安置 |
| 公示无依据 | 每个动作写审计日志（谁、何时、改前改后、IP），名单可反查 |

## 3. 核心功能

> 只列 MVP 必须跑通的 5 项。每项都可从接口独立验收。

### 功能 1：基础数据与轮次编排

实训室（名称、容量、方向、简介、开放日）、导师（所属实训室、名额、考核要求）、轮次（宣讲/开放日/填报/面试/确认/补录/调剂/公示，含起止时间）。

- **硬约束**：同一实训室内导师名额合计 ≤ 实训室容量；导师名额不得下调到低于已占用数。
- **验收**：建 3 个室共 30 个名额，超配时接口返回 `4001` 并说明具体数字。

### 功能 2：平行志愿填报

学生在一个轮次内最多填报 **3 个平行导师意向**（不区分先后），并声明是否服从"实训室内部调剂"与"全院跨实训室调剂"。

- **规则**：重复提交按"整体覆盖"处理（先删后插），不是追加；不存在的导师、已停用导师直接拒绝。
- **验收**：提交 4 个触发校验错误 `1001`；提交 3 个成功；再次提交后志愿数仍为 3。

### 功能 3：统一面试评分与选拔

按 **25 / 20 / 35 / 20** 四维评分（态度与动机、逻辑与表达、编程/专业基础、时间投入与协作），满分 100。

- **选拔规则**：按导师分别排序 → 前 N 名 `拟录取` → 内部调剂候选 → 递补 → 不推荐；同分按学号升序打破平局。
- **预演**：支持 `dry_run`，只看结论不写库，用于校验数据。
- **幂等**：同一轮次重复运行不会重复发意向。
- **验收**：名额 1、两人分数 100 与 36 时，只有 100 分者拿到待确认意向；重复运行第二次 `offers_created = 0`。

### 功能 4：拟录取确认与分轮补录

- 只有 1 个待确认意向 → 允许无参自动确认；≥2 个 → **必须传 `mentor_id`** 显式选择，否则 `4001`。
- 确认后其余意向自动置为"已放弃"；重复确认同一导师幂等返回，不重复扣名额。
- 逾期未确认 → 批量释放为 `expired`，名额回流；`fill-vacancy` 按顺位补 1 人（跳过已确认/已待确认者）。

### 功能 5：统筹调剂、公示与申诉

- **调剂**：内部调剂（同室、服从内调）→ 全院跨室调剂（服从跨调）→ 剩余进入约谈名单；管理员可对约谈学生做统筹安置。
- **公示**：创建公示草稿 → 发布 → 学生端可见。
- **申诉**：学生提交实名申诉（≥5 字）→ 监督/教务受理并写明处理意见 → 学生可查看结果。

## 4. 页面 / 模块结构

按控制台导航组织，共 6 个视图（`#/overview` … `#/public`）：

| # | 页面 | 路由 | 面向角色 | 主要内容 |
|---|---|---|---|---|
| 0 | 登录 / 公开落地页 | — | 全部 | 流程 5 步说明、统计数字、演示账号提示、公开信息入口 |
| 1 | 总览 | `#/overview` | 全部 | KPI（室/导师/名额/学生/志愿/面试/待确认/已确认）、开放轮次、待办提示 |
| 2 | 学生工作台 | `#/student` | 学生 | 我的阶段、我的志愿（含剩余名额）、我的意向、我的面试、我的申诉 |
| 3 | 选拔管理 | `#/admin` | 教务 | 跑选拔（含预演）、面试录入、意向列表、逾期释放、递补、调剂、约谈安置 |
| 4 | 监督与公示 | `#/review` | 监督 / 教务 | 公示发布、申诉受理、入组名单、审计日志 |
| 5 | 基础数据 | `#/data` | 教务 | 实训室、导师、轮次增改；演示数据重置 |
| 6 | 公开信息 | `#/public` | 游客 | 实训室与导师名额、开放轮次、已发布公示 |

**页面与后端对应**：以上视图消费同一套 `{code, message, data}` 响应；后端路由分组为 `auth` / `student` / `admin` / `publication`。

## 5. 设计与体验要求

> 以下取值取自现有样式令牌（`web/styles.css` 的 `:root`），作为**唯一视觉基准**，后续新增页面必须复用，不得另起色板。

### 5.1 视觉风格

**克制的事务管理台**：浅灰底 + 白色卡片 + 细边框，靠留白和层级区分信息，不靠阴影和色彩堆叠。数据密集但可读，重点用徽章颜色而非大色块表达状态。

### 5.2 设计令牌

| 类别 | 令牌 | 值 |
|---|---|---|
| 主色 | `--brand` / `--brand-dark` / `--brand-soft` | `#3355eb` / `#2540c4` / `#eef1ff` |
| 背景 | `--bg` / `--bg-soft` | `#f4f5f7` / `#fafbfc` |
| 容器 | `--surface` / `--surface-2` / `--border` / `--border-strong` | `#ffffff` / `#f7f8fa` / `#e4e7ec` / `#d3d8e0` |
| 文字 | `--text` / `--text-2` / `--muted` | `#171a1f` / `#4b5563` / `#8a919e` |
| 语义色 | 成功 / 警告 / 危险 / 信息 | `#0f8a5f` / `#a86400` / `#b42318` / `#1f6feb` |
| 圆角 | `--radius` / `--radius-sm` | `12px` / `8px` |
| 阴影 | `--shadow-sm` / `--shadow` / `--shadow-lg` | `0 1px 2px` / `0 6px 24px` / `0 24px 60px`，rgba(16,24,40,…) |

### 5.3 字体与间距

- 正文字族：`Inter` → 系统字体 → `Segoe UI` / `Microsoft YaHei` / `PingFang SC` / `Noto Sans SC`。
- 等宽（数字、编号、日志）：`JetBrains Mono` / `Consolas`。
- 基准字号 `14px`，行高 `1.55`；层级靠 13/14/16/20/28px 五档区分，不使用奇数字号。
- 间距体系按 4 的倍数（4/8/12/16/24/32），卡片内边距 20-24px。

### 5.4 状态色彩映射（必须一致）

| 状态 | 色调 | 说明 |
|---|---|---|
| `pending` 待确认 / `open` 进行中 | warn 橙 | 需要用户动作 |
| `confirmed` 已确认 / `published` 已发布 / `proposed` 拟录取 | success 绿 | 终态或正向结果 |
| `waitlist` 递补 / `accepted` 已受理 | info 蓝 | 中间态、待定 |
| `internal_candidate` 内调候选 | brand 主色 | 与普通递补区分 |
| `rejected` 已放弃 / `expired` 已逾期 / `closed` 已关闭 | neutral / danger | 结束态 |

### 5.5 设备适配

| 设备 | 断点 | 要求 |
|---|---|---|
| 桌面 | > 1080px | 主形态：多列网格 + 侧边导航 |
| 平板/窄桌面 | ≤ 1080px | 卡片网格降列，筛选栏折行 |
| 手机 | ≤ 860px | 单列堆叠、表格横向滚动或转卡片、导航折叠为顶部 |

### 5.6 交互要求

- 破坏性操作（重置演示数据、删除实训室、逾期释放）必须二次确认。
- 写操作成功 → 局部刷新 + 轻提示（toast）；失败 → 直接展示后端 `message`，不吞错误。
- 空状态必须给"下一步做什么"，而不是只写"暂无数据"。
- 键盘可达：焦点可见、弹窗可 Esc 关闭、操作后焦点回到原位置。
- 状态同步：同一数据被他人改动时，页面通过事件流自动刷新，不要求手动重载。

## 6. 技术约束

| 项 | 约束 |
|---|---|
| 后端栈 | Python 3.12 + FastAPI + SQLAlchemy 2.x + SQLite（生产可切 PostgreSQL） |
| 前端栈 | 原生 ES Module + 模板字符串渲染，**无框架、无构建步骤** |
| 接口契约 | 统一 `{code, message, data}`；错误码 `1001/2001/3001/4003/4004/4001/5000` 不可更改 |
| 不可改动 | 领域算法签名（`total_score` / `rank_interviews` / `confirm_unique_offer` / `expire_pending_offers` / `next_waitlist_candidate` / `plan_adjustments`）；上述错误码含义；四维分值上限 25/20/35/20 |
| 样式方案 | 单文件 CSS + CSS 自定义属性，禁止引入 UI 组件库或 CSS-in-JS |
| 数据 | 演示数据由种子脚本生成，可一键重置；数据库文件与 `.env` 不入库 |
| 协作 | `main` 受保护；`ruff` + `pytest` 必须通过；接口变更需同步 `docs/design.md` |

## 8. 验收标准

### 8.1 功能验收（可逐条勾选）

- [ ] 学生能完成：登录 → 填 3 个志愿 → 看到面试结果 → 确认唯一去向。
- [ ] 教务能完成：建室建名额 → 录入评分 → 跑选拔（含预演）→ 逾期释放 → 递补 → 调剂 → 发布公示。
- [ ] 多意向学生不选导师时被拒绝，提示明确；选后其余意向自动置为放弃。
- [ ] 同一轮次重复跑选拔不产生重复意向。
- [ ] 导师名额超容量、名额下调低于已占用数，两种情况均被拦截。
- [ ] 学生越权访问管理接口返回 `4003`；未登录返回 `2001`。
- [ ] 关键动作可在审计日志中查到（含操作者、动作、前后值）。
- [ ] 申诉从提交到受理全流程可跑通，学生能看到处理意见。

### 8.2 体验验收

- [ ] 桌面（1440px）与手机（390px）均无横向溢出、无重叠、无文字截断。
- [ ] 所有状态徽章颜色符合 5.4 映射表。
- [ ] 空状态、加载态、错误态均有明确反馈，无白屏。
- [ ] 控制台无报错，网络面板无失败请求。

### 8.3 工程质量验收

- [ ] `pytest backend/tests -q` 全绿（当前 33 条）。
- [ ] `ruff check backend/app backend/tests scripts` 无告警。
- [ ] CI（GitHub Actions）在 PR 上通过。
- [ ] `data/*.db`、`.env`、`.venv/` 未入库。

## 9. 暂不做的事情

### 9.1 本期不做

- 统一身份认证 / OIDC 接入（保留 `DEMO_MODE` 演示登录）。
- 多评委加权评分、评分仲裁与改分审批流。
- 移动端原生 App、微信小程序。
- 名单导出 PDF/Excel、打印排版。
- 消息通知（短信/邮件/站内信）。
- 高并发优化（行级锁、Redis 限流）——校级规模当前不构成瓶颈。

### 9.2 以后考虑

- 面试排期与签到（时间段、教室、候场队列）。
- 导师端独立视图（当前导师能力由教务代办）。
- 多轮次历史对比与数据看板（录取率、调剂率、专业分布）。
- 名单异议的批量复核与一键回滚。
